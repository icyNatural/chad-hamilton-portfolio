# Project Content Map

> Phase 1 evidence map. “Candidate” means suitable for later review, not approved for copying or publication. An exact product-name match is never inferred from visual similarity alone.

## Confidence key

- **Verified** — a repository README/source explicitly establishes the identity or relationship.
- **Qualified** — evidence supports a relationship, but not an exact product-name or implementation claim.
- **Ambiguous** — a visual or conceptual resemblance exists without enough provenance.
- **Needs assets** — implementation/content evidence exists, but there is no sufficiently attributable portfolio media.

## Asset-selection rules by evidence strength

### Primary product proof

Use clean full-interface captures that visibly show a verified workflow or model state. Prioritize:

1. Energy Engine dashboard, energy field, recovery, and pattern views.
2. IcySense onboarding, scan modes, camera state, and structured result.
3. Icy Game OS dashboard and state controls.
4. Human State Atlas/Atlas ecosystem only after source-to-repository provenance is confirmed.
5. Inquiry and language-system interfaces with the relationship between repositories clearly explained.

### Secondary process evidence

Use sparingly in case-study implementation sections:

- clean API documentation;
- sanitized terminal output;
- architecture/repository structure;
- graph and timeline interaction states;
- installer/automation flow.

### Exclude from public project galleries

- file explorers and disk diagnostics;
- deployment/domain dialogs;
- failed builds, test errors, and missing-camera/error states unless the case study is explicitly about debugging;
- AI-chat windows and generated-app-builder panes;
- unrelated social posts, videos, third-party research, maps, books, and music screens;
- personal/source photos;
- generated apparel/logo mockups as evidence of software implementation;
- Astro/React/Vite starter artwork.

## Provenance and duplication decisions

- Treat this portfolio repository as canonical for the current ten project PNGs and site assets; the `icy-clear-ecosystem/chad-hamilton-portfolio` copies are duplicate backup/context only.
- Treat repository-owned media as canonical over identical copies in chat/source archives. Example: `language-execution-framework\assets\behavior.png` is canonical, not its identical ecosystem copy.
- Treat the two `value-formation\chart.png` copies as one ambiguous shared artifact until a canonical project is established.
- AI-generated DALL·E/WebP content can support disclosed visual exploration, but cannot establish implementation, results, authorship of third-party source material, or product completeness.

## Content facts safe to use

- Energy Engine has both a static demonstration layer and a documented Python/full-engine architecture.
- IcySense v1 implements the interaction loop but uses a placeholder local classifier.
- Icy Game OS is explicitly a starter UI, not a finished game platform.
- Human Operating System is a public systems/research repository, not itself proof of the requested “Ancient Human Energy Lab” brand.
- Day State documents an eight-category local state selector with browser persistence and JSON export.
- Autonomic Regulation Model is explicitly designed for integration into larger systems including Energy Engine.

## Claims requiring owner confirmation before redesign

1. Whether Cognitive Mode Engine, Inquiry Backend, and Inquiry Engine are one product, successive versions, or separate systems.
2. Whether Potent Library and Potent Lexicon are the same product, and how Language Execution Framework relates.
3. Whether WorldLens and Visual Lens are intended aliases or successors to IcySense.
4. Which screenshot-archive Atlas/Ecosystem screens belong to `human-state-atlas`.
5. Whether Ancient Human Energy Lab, Scenario States, Icy Chaos Engine, and Life Chronicle exist outside the audited repositories.
6. Which projects and images may be publicly disclosed, especially health-state data, personal photos, local paths, prompts, and third-party reference material.
